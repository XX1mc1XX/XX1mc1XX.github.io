> 这是一个**合作开发的开源项目**，我是贡献者之一（仓库共 3 位贡献者）。

Wovra 是一个实验性系统，用来组织和管理人类与 AI 之间复杂、长时运行的工作。

它不把 AI 智能体看成一段不断累积上下文的连续对话，而是**把一个任务看成持久的工作空间**——拥有自己的状态、上下文、进度、历史、智能体、报告和评估。

目标不是让 AI 更聪明，而是让 AI 的工作变得**可管理、可观察、可引导、可恢复**。

## 要解决的问题

长时运行的任务带来的是一类新问题：

- 随着对话和工具调用的累积，**上下文持续增长**
- 一个微小的改动，可能要随身携带大量无关的历史信息
- 失败之后难以回退到某个已知良好的状态
- 人在中间想介入引导时，找不到一个合适的落点

## 它在整个链路里的位置

```
                    Human（人类）
                      │
                 需求 / 反馈
                      │
                      ▼
              ┌───────────────┐
              │     Wovra     │
              │               │
              │  任务管理      │
              │  上下文        │
              │  状态          │
              │  报告          │
              │  归档          │
              │  评估          │
              └───────┬───────┘
                      │
                智能体编排
                      │
          ┌───────────┼───────────┐
          ▼           ▼           ▼
       Agent A     Agent B     Agent C
          │           │           │
          └───────────┼───────────┘
                      │
                      ▼
              现有智能体运行时
                      │
          ┌───────────┼───────────┐
          ▼           ▼           ▼
        文件        Shell        工具
```

**Wovra 不替代底层的智能体运行时**，它管的是上面那一层：任务怎么拆、上下文怎么装配、多智能体怎么分工、人怎么介入。

## 代码组织

```
src/wovra/
  agent/          Agent 运行时（由四个 mixin 组装）
    core.py         运行循环、轮生命周期、工具分发、用量记账、轮闭合结算链
    assembly.py     共享历史装配（段落档 + 近期原文）、fork 基线、路由裁剪
    maintenance.py  水位闸门、每轮结算、折档线、分域、增量落地、回落
    ledger.py       todo（大步 / 小步）、notify / consult、提交守卫
    prompts.py      模型可见的提示装配
  pathmatch.py    路径的鲁棒匹配（把模型抄错的路径形态归一）
  attachments.py  粘贴 / 上传的附件
  observed.py     观察快照 + 「你读过的文件已改动」通知
  registry.py     职责注册表（域树 → agent 条目）
  routing.py      路由规则、身份卡、职责表（谁管什么）
  economics.py    分域判据（该不该裂、在哪层裂）
  split_lifecycle.py  分域生命周期
  serve.py        Web 服务（HTTP API + 静态前端）
webui/            人视图前端（纯静态：index.html + vendor）
```

几个值得注意的设计：

**上下文分档**：历史不是一条无限增长的线，而是「段落档 + 近期原文」两层，配合水位闸门在超过阈值时结算折档——把久远的细节压成段落摘要，近期保持原文。

**分域**：任务可以按「域」拆给不同 agent，什么时候该裂、在哪一层裂，由一套明码的判据决定（`economics.py`），而不是拍脑袋。

**模型会抄错路径**：`pathmatch.py` 专门处理这个——把模型产出的路径形态归一，再去匹配真实文件。这类「模型不可靠」的工程防护在项目里随处可见。

## 怎么跑

```bash
wovra serve                 # 默认 http://127.0.0.1:8600/
wovra serve --port 8612     # 换端口（可多实例并存）
WOVRA_TASKS_ROOT=/tmp/demo wovra serve   # 用另一份数据目录起演示实例，不碰真实会话
```

WebUI 是纯静态页面，不依赖前端构建工具链。
