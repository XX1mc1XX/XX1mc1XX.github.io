## 这个项目解决什么问题

做过工业相机控制软件的人都见过那个界面：相机参数（曝光、增益、帧率、触发模式、ROI）、光源参数（亮度、频闪、触发延时）、算法参数（阈值、滤波核、ROI）、运动参数（速度、加速度、回零模式）——几十上百个参数，分门别类塞在四五个面板里。

用户想调一次曝光，得先找到对的菜单、对的对话框、对的输入框。新用户甚至不知道该调曝光还是增益——**他只知道「画面太暗」**。

这就是 agent4cpp 要打通的那条通道：**自然语言 → C++ 函数调用**。

有一点我的想法比较明确：**不要把所有按钮都改成 AI 控制**。正确的做法是保留现有界面，另加一个「AI 助手」入口——想精确控制时用原来的方式，想快速完成常见操作时用一句话。两条路并存，而不是替代。

**先看它跑起来是什么样。** 左边是接进来的 Qt 日志分析助手，右边是命令行模式——两个前端，同一个 Agent 内核：

![运行效果：Qt 界面与命令行](/images/agent4cpp/项目效果1.webp)

## 一、整体是怎么转起来的

从用户说一句话到设备真的动了，中间经过这些环节：

![工具调用流程](/images/agent4cpp/lesson04-工具调用流程.svg)

![核心类图：这条链路上有哪些类](/images/agent4cpp/第1章_项目总览与架构设计-2.svg)

| 环节 | 谁在干 | 干什么 |
|---|---|---|
| 听懂人话 | LLM Client | 把「图像太暗」连同工具清单发给模型 |
| 决定调什么 | 模型 | 返回一个 `tool_call`：我要调 `set_exposure`，参数 8000 |
| 找到那个函数 | Tool Registry | 按名字查出注册过的 C++ 函数，校验参数 |
| 真的动手 | 业务代码 | 调用 `camera->setExposure(8000)` |
| 记下结果 | Agent | 把执行结果塞回对话记录 |
| 判断要不要再调 | 模型 | 还要工具就再来一圈，不要了就总结成一句话 |

**这条链路里最重要的一条界线**：模型**从头到尾没有执行任何代码**。它只会输出文本说「我要调 set_exposure」——真正碰设备的是 C++ 这一侧。

对工业软件来说这就是安全边界：**模型只能从你注册过的工具里挑，挑不出范围**。

## 二、模块怎么分

整个库分八个模块，每个模块只依赖它该依赖的东西：

![模块与目录结构](/images/agent4cpp/第4章_项目结构与代码组织-1.svg)

```
include/agent4cpp/          对外公开的 SDK 头文件（13 个）
src/
  agent/       Agent Runtime —— 工具调用闭环与运行时
  tool/        Tool 与 ToolRegistry —— 工具描述、注册、调用
  llm/         LLM Client —— Mock 与 OpenAI-compatible 两种实现
  http/        HTTP 客户端 —— 基于 libcurl
  knowledge/   本地知识库 —— 文档加载与检索
  log/         日志 —— 基于 spdlog
  cli/         交互式命令行
  core/        Status 状态码 + nlohmann/json
examples/
  camera_mock/           无需 API Key 的相机 Mock 示例
  openai_camera_cli/     接真实模型的 CLI 示例
  qt_log_analyzer/       Qt Widgets 日志分析助手
```

**它是个能编译能跑的完整工程**——下面这张是 Visual Studio 里的样子：左边是对外头文件，右边八个实现模块，下面那次构建把库、三个示例和全部测试一起编了出来。

![Visual Studio 里的工程结构与构建结果](/images/agent4cpp/构建截图-VS解决方案.webp)

**三个能力层各有一个纯虚接口**，模式完全一样：

| 接口 | 实现 |
|---|---|
| `ILLMClient` | `MockLLMClient` / `OpenAICompatibleLLMClient` |
| `IHttpClient` | `CurlHttpClient` |
| `IKnowledgeStore` | `InMemoryKnowledgeStore` |

这不是为了「面向对象好看」——**Mock 客户端让整条链路能在没有网络、没有 API Key、不花钱的情况下跑通并写断言**。开发期用 Mock 联调，上线换真模型，上层调用与工具注册零改动。

## 三、逐个模块说设计

### 1. Tool 模块：工具是声明出来的

![Tool 模块内部结构](/images/agent4cpp/第6章_Tool_模块设计与实现-1.svg)

新增一项可被大模型调用的设备能力，只需要**两步**：先用 `AGENT4CPP_TOOL` 宏声明一个函数（宏体就是你写的业务逻辑），再用 `AGENT4CPP_REGISTER_FUNCTION` 把它登记进注册表。JSON Schema 由宏和运行时注册表**自动生成**——手写 Schema 的工作量是零。

**这里有个细节值得一提**：`AGENT4CPP_TOOL` 的第二个参数**是纯装饰**——宏体根本没用它，写在那里只是为了让人读代码时一眼知道这个工具干什么。真正生效的描述来自注册那一步。

这种「看着有用其实没用」的地方，只有真读过宏展开才会发现。

配套**六类参数构造宏**（整数 / 浮点 / 字符串 / 布尔 / 枚举 / 数字），另外还有对应的宏可以把 C++ 对象方法直接注册成工具——既有设备代码接入时不需要改造。

![工具内部分层](/images/agent4cpp/lesson12-工具内部分层.svg)

**参数校验放在工具层而不是业务层**。模型传错参数是常态，校验前移到框架里，业务函数就能假定拿到的参数是合法的。校验失败返回结构化错误而不是抛异常，因为这个错误要回灌给模型看。

![封装路径](/images/agent4cpp/lesson12-封装路径.svg)

### 2. LLM Client：模型厂商的差异收在一处

`OpenAICompatibleLLMClient` 负责请求构建与响应解析，包括最麻烦的那部分——**流式响应里 `tool_calls` 的分片拼接**。

![消息形状](/images/agent4cpp/lesson09-消息形状.svg)

同一条消息按角色要拼成不同形状，这是 OpenAI 协议里最容易写错的地方：assistant 带 `tool_calls` 但 `content` 可以是空、tool 消息必须带 `tool_call_id`、`reasoning_content` 下一轮要原样回传（不回传，长对话到第四轮就开始报 400）。

![真实往返](/images/agent4cpp/lesson09-真实往返.svg)

### 3. HTTP 客户端：libcurl 的两个坑

![curl 流程](/images/agent4cpp/lesson08-curl流程.svg)

**CA 证书路径。** `ca_bundle_path` 的默认值是相对路径 `curl-ca-bundle.crt`，libcurl 找不到就直接失败。解决办法是把它和 `libcurl-x64.dll` 一起拷到可执行文件同目录。

**两种失败要分开。** 网络层失败（连不上、证书错）和协议层失败（HTTP 4xx / 5xx）是两回事，混在一起报错会让排查方向完全错。

![两种失败](/images/agent4cpp/lesson08-两种失败.svg)

### 4. Agent Runtime：整个项目的心脏

![Agent 与周边类的关系](/images/agent4cpp/第9章_Agent_Runtime_模块设计与实现-1.svg)

核心是一个函数 `RunLocked()`。它很长，但**真正的逻辑只有五步**——问模型、看它还要不要工具、要就执行、把结果塞回记录、回到第一步再问。

![Agent 循环](/images/agent4cpp/lesson10-Agent循环.svg)

程序里**没有一行代码判断「任务完成了没有」**——没有 `if (曝光调好了)`。这个判断完全在模型那边：它觉得够了，就不再要工具。代码只认一个信号：**有没有 `tool_call`**。

这个决定我一开始绕了很久才接受。程序根本没法知道「曝光该调到多少才算调好」，那需要领域知识，而知识在模型那边。硬要在代码里判断，就得给每个任务配一套规则，框架的通用性就没了。

配套两条兜底：

- **步数上限**：转到上限还没停就强制收敛，防止模型在两个工具之间来回横跳
- **工具失败同样回灌**：失败信息以「可重试」的语义驱动模型下一轮自我修正，而不是中断或静默失败

![对话记录增长](/images/agent4cpp/lesson10-对话记录增长.svg)

上面这张图是一圈一圈转下来的完整痕迹：每圈加两条（模型的话 + 工具结果），最后那条没有 `tool_call`，循环就停在那。

### 5. Knowledge 模块：关键词打分，以及一个真实缺陷

知识库用的是**关键词打分**而不是向量检索——因为工业现场经常离线，装不了向量库；而且出问题时工程师需要知道「为什么检索到了这一段」，余弦相似度 0.83 等于没说。

代价也很实在：同义词不认、中文分词粗糙。而且代码里有个真实缺陷——**按字节切块会把中文切成非法 UTF-8**：

![字节切开中文](/images/agent4cpp/lesson11-字节切开中文.svg)

这一块单独写了一篇：[给 Agent 配一个资料柜](/blog/knowledge-store-keyword-search/)

### 6. 日志与 Status：可观测性和统一错误

**每轮执行的 step 序号、工具名、入参、返回状态与结果 payload 全部结构化落盘**，现场问题能按时间轴回溯，而不是面对一堆散落日志猜。

Status 模块统一了错误返回——**不用异常，用返回值携带错误码与描述**。理由是异常在跨 DLL 边界和异步场景里很难处理，而工业软件这两件事都会遇到。

## 四、三个示例，从零依赖走到真接入

示例不是为了演示 API，而是**把一条路径走到头**：

![界面边界](/images/agent4cpp/lesson13-界面边界.svg)

| 示例 | 用到什么 | 走通什么 |
|---|---|---|
| `camera_mock` | **不用任何 API Key** | 用 Mock 客户端把「自然语言 → 工具调用 → 设备执行 → 结果回灌」整条闭环跑一遍 |
| `openai_camera_cli` | 真实模型 + CLI | 接 DeepSeek / OpenAI，命令行里真的跟设备对话 |
| `qt_log_analyzer` | Qt Widgets | 把 Agent 嵌进图形界面：日志着色、行号定位、后台线程跑 Agent |

第三个示例最能说明「可迁移」这件事——它把同一个 Agent 内核接进了 Qt 界面，界面层只需要关心怎么把用户的话交给 Agent、怎么把结果渲染出来。

![示例三：Qt 日志分析助手的整体架构](/images/agent4cpp/第15章_示例三_Qt_日志分析助手架构-1.svg)

![示例运行效果：一份日志丢进去，助手自己调工具去查](/images/agent4cpp/项目效果2.webp)

![示例一：Mock 相机的演示链路](/images/agent4cpp/第13章_示例一_camera_mock_演示-1.svg)

**界面里必须用异步接口。** 同步跑一次模型调用要十几秒，会直接冻住界面——这是我接 Qt 时踩的第一个坑。

## 五、怎么测

![可测边界](/images/agent4cpp/lesson14-可测边界.svg)

测试的思路是**把测不了的部分隔离掉**：模型不可控、网络不可靠，但工具注册、参数校验、Schema 生成、消息拼装这些都是纯逻辑。

Mock 客户端在这里的价值就体现出来了——它让整条 Agent 链路可以在没有网络的情况下跑断言，测试里能写「给它这个工具调用序列，它应该在第几轮停」。

![两条验收路](/images/agent4cpp/lesson14-两条验收路.svg)

## 六、收益及对比

| 维度 | 传统实现 | 本项目 | 收益 |
|---|---|---|---|
| 工具接入 | 逐个手写 JSON Schema | 声明函数 + 1 行注册，Schema 自动生成 | **手写量 归零** |
| 参数类型 | 每类参数各写一套构造 | 内置 6 类参数构造宏 | **覆盖 6 类** |
| 既有代码接入 | 需改造适配 | C++ 对象方法直接注册 | **改造量 0** |
| 更换大模型 | 改遍上层调用与工具注册 | 替换 1 处接口实现 | **上层 零改动** |
| 开发联调 | 需 API Key 与真实网络 | 本地 Mock 客户端跑通全链路 | **0 Key / 0 请求** |
| 多轮调用收敛 | 多轮调用可能不收敛 | 「模型不再请求工具」唯一终止 + 步数上限 | **风险 归零** |
| 工具执行失败 | 中断或静默失败 | 回灌错误状态与结构化结果，驱动模型自纠 | **可自恢复** |
| 问题排查 | 日志散落、难以复现 | step 级结构化落盘 | **按时间轴回溯** |
| 设备与模型耦合 | 设备代码耦合模型细节 | 设备侧与模型侧双向解耦 | **双向 解耦** |

**业务价值**：新增设备能力从「改代码」变为「声明函数」，更换大模型不动上层，没有 API Key 也能开发联调——把工业设备的自然语言入口做成**可复用的底座**，而非一次性演示。
