面向工业机器视觉产线，把既有的 C++ 设备函数（相机状态查询、参数读写、曝光调节、运动控制卡）封装成大模型可调用的工具，覆盖「**自然语言输入 → 模型决策 → 工具调度 → 设备执行 → 结果回灌 → 终答**」全链路。

设备的操作入口从「人工翻菜单、逐个填参数」变成一句自然语言；模型侧用统一抽象接口隔离厂商，开发期用本地 Mock 客户端离线联调，上线切换到真实大模型时，上层调用与工具注册零改动。

## 工具接入压到一行注册

新增一项可被大模型调用的设备能力，只需**「声明函数 + 一行注册」**——JSON Schema 由宏与运行时注册表自动生成，手写 Schema 的工作量是零。

配套**六类参数构造宏**（数字 / 整数 / 浮点 / 字符串 / 布尔 / 枚举），并支持把 C++ 对象方法直接注册为工具，既有设备代码接入时不需要改造。

## 模型接入层统一抽象

模型厂商的差异收敛到**单个接口实现**，换大模型只改这一处，上层调用与工具注册零改动。

| 接口 | 实现 |
|---|---|
| `ILLMClient` | `MockLLMClient` / `OpenAICompatibleLLMClient` |
| `IHttpClient` | `CurlHttpClient` |
| `IKnowledgeStore` | `InMemoryKnowledgeStore` |

三个能力各自一个纯虚接口，模式一样：**上层只依赖抽象，实现可换**。这不是为了"面向对象好看"——Mock 客户端让整条链路能在没有网络、没有 API Key、不花钱的情况下跑通并写断言。

## 循环以收敛为唯一终止条件

多步工具调用循环的判断只有一条：

```cpp
// 模型这一轮没有要求调工具，就是它认为可以回答了
if (response.tool_calls.empty()) break;
```

不猜、不发散。配套两条兜底：

- **步数上限**：转到上限还没停就强制收敛，防止模型在两个工具之间来回横跳
- **工具失败同样回灌**：失败信息以可重试的语义驱动模型下一轮自我修正，而不是中断或静默失败

## 传输与工具描述层

基于 **libcurl** 完成与模型 API 的请求响应传输；工具描述层统一承载工具用途说明与参数 Schema，模型侧仅凭描述选择工具。

## 离线联调

模型接入层抽象成统一接口后，开发期用**本地 Mock 客户端**跑通全链路——**0 个 API Key、0 次网络请求**即可验证「自然语言 → 工具调用 → 设备执行 → 结果回灌」这个闭环。

## 可观测性

每轮执行的 **step 序号、工具名、入参、返回状态与结果 payload 全部结构化落盘**，现场问题能按时间轴回溯，而不是面对一堆散落的日志猜。

## 知识库与 CLI

接入本地知识库检索为模型回答补充设备侧知识；配套交互式 CLI，命令行即可完成会话与工具调用验证。

知识库这一块值得单独说——用的是**关键词打分**而不是向量检索，而且代码里有个真实缺陷（按字节切块会把中文切成非法 UTF-8）。单独写了一篇：[为什么我没给这个 Agent 接向量数据库](/blog/lightweight-rag-keyword-search/)
