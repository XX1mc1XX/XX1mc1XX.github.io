这个系列的第一篇里有一句话被反复引用：**"截断省 token"是幻觉。** 那一篇是从三个想当然的层面讲的，这一篇是它的正面战场——**一个具体的任务，在三代机制下各跑一次，看截断是怎么从"省一点"变成"全盘崩"的。**

先把主角交代清楚：任务只有一个，**给一个约 42KB 的单个 HTML 文件加功能**。同一个会话、同一个文件、同一句用户输入，在三代上下文机制下各执行一次。三代机制之间只差两件事——**要不要在轮内折叠上下文，要不要把工具结果截断到 2KB。** 就这么点差别，跑出来一个 39 → 11 → 3 的读取次数曲线，和两次彻底翻车。

为什么用"单个大文件"做任务，也说一句，因为它不是随便挑的。**单文件、同文件、无需跨文件跳转**——这排除了"读错文件""依赖关系复杂"这些干扰变量，把整个实验收缩到一件事上：**同一份材料，在不同截断策略下，模型要读它多少遍。** 变量的干净，是这个实验可信的前提，也是它的边界。

## 三代机制，一张表

![同一个文件，三代机制：39 → 11 → 3 次读取](/images/wovra/三代机制.svg)
| | 尝试 1<br>轮内折叠 + 2KB 截断 | 尝试 2<br>不折叠 + 2KB 截断 | 尝试 3<br>零截断 |
|---|---|---|---|
| **结果** | ✗ 撞 40 步上限，**仅 3 处编辑** | ✗ 用户中断，**0 处编辑** | ✓ 完成，6 组新功能 |
| 工具调用 | 56 次（读 39 / 搜 8 / 改 9 / 列 1） | 11 次（**全是读**） | 23 次（读 3 / 改 18 / 跑 2） |
| 读取区间 | 大量重叠 | 11 段不重叠，每段只见前 2KB | (1-400)(401-800)(801-1134)，**理论最小** |
| 名义 token | 未记账（当时开放轮无 usage） | **110,080** | **374,732** |
| 缓存命中 | 未落盘 | 87.3% | **89.8%** |
| 等效输入 | 未落盘 | **≈16,675** | **45,612** |

**"次读取"这个词，指的是 `read_file` 工具调用**——字面意义上的读文件次数，从 `task.json` 的工具调用记录里数出来的。不是抽象的"轮次"，是一次一次真去读那个文件。

这张表里藏着两个反直觉，都需要单独讲清楚。但在讲它们之前，先把三代机制之间**到底改了什么**摆出来，因为这条改动序列很短，短到容易被忽略：

```text
尝试 1 → 尝试 2：废除轮内折叠（50 事件软限制）
尝试 2 → 尝试 3：废除 2KB 安全截断（SAFE_RESULT_LIMIT）
               + 加入窗口保底（估算 > 窗口 × 90% 才紧急折叠）
               + 加入文件地图
```

两处改动，都发生在"要不要在执行期切上下文"这一个维度上。**三代机制的差别不是"三个不同的算法"，是同一套机制在截断这件事上的三个松紧档位。** 这正是这个实验干净的地方——变量少。

## 第一代：折叠造出的失忆循环

第一代的机制叫"轮内折叠"——50 个事件的软限制，超过就把早期事件折叠成一行索引。

它的死法很典型，而且是一个**正反馈**：轮内折叠会把**模型在同一轮里刚读到的文件内容**也折成一行索引。于是形成一条循环：

```text
读文件 → 事件数上涨 → 早期的读取被折叠 → 模型"失忆" → 重读 → 事件更多 → 折叠得更快
```

实测的读取区间序列是这样的：

```text
694-1003 → 700-769 → 864-1003 → 884-933 → 960-1003 …
```

同一段区间反复读。**39 次 `read_file` 里大量是重读**，40 步上限烧完，只落地了 3 处编辑，98 个事件全部沉没。

这里的关键不是"折叠不好"，是**折叠把模型自己的记忆也当成了垃圾收走**。它省下的是上下文里那点重复内容，代价是模型每一轮都要重新找回自己刚看过的东西。**省的地方和执行的地方，是同一个地方。**

## 第二代：2000 字符的锁孔

第一代的折叠被废除之后，读取区间确实不再重叠了——11 段互不重复，看上去是一个进步。**但它死得更彻底。**

每一段读取结果将近 20KB，进入上下文时被截断到前 2000 字符（`SAFE_RESULT_LIMIT`）。**模型面对的是一个 2000 字符的锁孔**，只能一寸一寸地蹭完整个 42KB 的文件。那一轮的账是：**11 万名义 token 全部沉没，零产出，用户主动按下了中断。**

这里有一个必须讲透的细节，因为它是整篇文章的智力核心之一。**模型一次都没有调用 `expand_history`——零次。** 那个工具号称能把内容"展开成完整原文"，但它的上限被写死在一个 `[:4000]` 的截取上。对一个将近 20KB 的结果，"取回完整原文"这个承诺根本兑现不了。

**模型正确地拒绝使用一个坏掉的把手。** 它不是没想到这条路，是判断出这条路走不通。我们后来意识到一件很重要的事：**一个清醒的模型对残缺的工具有免疫力——它不会去够一个够不到的东西，它只会绕路，而绕路的代价就是那 11 万沉没的 token。** 所以"给个截断的把手、指望模型自己补救"这条路，从设计上就不成立。

## 第三代：零截断，三次读完

第三代废掉了 2KB 截断，同时补了两个东西：**窗口保底**和**文件地图**。

文件地图把降档历史里的文件列成"路径 + 读/写轮次"的清单注入装配，模型一眼就能定位该读哪个文件，不用盲目重爬。实测读取区间是：

```text
(1-400)(401-800)(801-1134)
```

**恰好是理论最小值**——三次读完全文，零重叠。随后 18 次 `edit_file` 精准落地，一轮闭合，完成了 6 组新功能。

文档里对这件事的总结我们很喜欢：**没有任何一步花在"找回本该在眼前的东西"上。**

这句话是三代对比的全部意义所在。第一代把力气花在重读，第二代把力气花在蹭锁孔，第三代把力气花在干活——**18 次编辑对 3 次、对 0 次。**

## 最反直觉的一组数：便宜的失败，贵的成功

如果只看到这里，结论还是"零截断更好"。但账本给出了一个更狠的对照，**它直接推翻了"截断更省"的直觉**：

| 口径 | 尝试 2（失败） | 尝试 3（成功） |
|---|---|---|
| 名义 token | 110,080 | 374,732 |
| 缓存命中 | 93,120（87.3%） | 310,400（**89.8%**） |
| **等效输入**（未命中 + 命中/30） | **≈16,675** | **45,612** |
| 产出 | **0 处编辑** | 6 组新功能 |

看清楚第二行和第三行。**失败的那一轮，等效输入约 1.67 万；成功的那一轮，约 4.56 万。** 按"省 token"的口径，截断那一轮做得**比成功轮更好、更便宜**。

所以我们后来推翻截断，**不是因为"截断更贵"**。按等效成本算，截断那一轮甚至更便宜。推翻它，是因为那一轮**产出为零**。文档里那句话写得很准：**省上下文的机制省错了地方，钱花了，活没干。**

**等效输入是唯一的成本口径，但它只在"活干成了"的前提下才有意义。** 省下来的 token 换不来任何东西，那这些 token 省得再漂亮，也是纯损失。这是整篇文章最重要的一句话，也是第一篇那个想当然的原始出处。

## 零截断凭什么不贵：它的浪费自己买得起

上面那个表还有一个方向要讲，不然会被误读成"零截断其实还挺贵"。

第三代的名义 token 是 374,732——**37 万，看着像一个天文数字。** 直觉上"不截断"当然贵。但零截断让单轮名义 token 膨胀，**代价是它把追加式的事件流变成了前缀缓存的最优布局。**

追加式意味着每一轮 prompt 的**前缀不变**——历史只往后加，前面的字节一个都不动。这正是前缀缓存最想要的形状，于是 89.8% 的命中把真实成本压到了 45,612 等效输入。**零截断在缓存定价下反而是最便宜的策略，它的那点"啰嗦"通过缓存对齐，自己把自己付掉了。**

反过来看截断：它明文省下的那点上下文，代价是重读的步数。**省的是小钱，赔的是整轮。**

还有一个口径值得单独摆出来，因为它经常被混掉。**名义 token 是"多步累加"，等效输入是"实际重量"。** 37.5 万这个数不是某一步的 prompt，是整轮每一步 prompt 加起来的总和——它看着吓人，是因为它把"每一步重发一遍历史"全算了进去。而在缓存定价下，重发的那部分走的是折扣价，真正有重量的是没命中的那点。这就解释了为什么 37 万的名义能压到 4.6 万等效：**它不是"便宜"，是"重复的部分打了折，只有新增的那点要按原价买"。**

这也是我们后来反复说的一句话：**名义 token 和实际成本在缓存定价下能差一个数量级。** 只看名义，你会对着 37 万惊慌、对着 11 万放心；换成等效输入看，谁贵谁便宜恰好是反的。

## 设计定稿：执行期零截断

这个实验跑完，定下了一条规则，它在文档里被反复重申：

> **执行期零截断，压缩只属于整理侧。**
> 轮内事件全量进上下文，内容不做任何剪切；唯一的天花板是模型窗口（估算超过 `WOVRA_CONTEXT_LIMIT` × 90% 时紧急折叠最老的事件）；窗口够大的时代，窗口本身就是最宽裕的资源——**省 token 的正确位置在整理，不在执行者的眼前。**

这条规则里最值得盯的是**"唯一的天花板是模型窗口"**这句话。它把"截断"从一个**常规手段**降级成了**最后手段**——而且是估算到快撑满窗口 90% 时的紧急动作。后面那个受控实验里，上下文峰值只到窗口的 3% 到 6.6%，**这条保底线根本碰不到**。也就是说，在实际负载下，"截断"这个机制几乎从不触发——它被设计在了模型根本到不了的地方。

这条规则还有一层容易滑过去的含义：**它把"压缩"这件事从执行期彻底搬走了。** 执行期的模型在做一件事——对着眼前的材料干活；任何在这条路径上删材料的动作，都会直接改变它能看到什么。而整理侧的模型在做另一件事——把一段已经闭合的历史，压成结构化的视图。**后者是"回头整理已经发生的事"，前者是"在发生的过程中抽走材料"，两者对模型的伤害完全不同。** 前者的代价是模型看不到某些东西，后者的代价是模型看不到它刚刚看过的东西——而后者，正是第一代那个失忆循环的根。

## 这三次读取不是运气

有一点必须说清楚，否则"3 次读取"会被误读成"这代模型比较聪明"。

**读取次数从来不是靠"让模型更聪明"降下来的，是把"它在找什么"这个问题直接从上下文里消掉。** 第三代之所以能三次读完全文，靠的是两个配套机制，不是模型忽然开窍：

- **文件地图**：把降档历史里的文件列成"路径 + 读/写轮次"的清单注入装配。模型一眼就知道该读哪个文件、哪个文件动过，不用盲目重爬。
- **`read_file` 的分段引导**：400 行一段的读法，让模型自然地按 (1-400)(401-800)(801-1134) 切分，而不是想起哪儿读哪儿。

**你看，这两样东西做的都不是"教模型怎么读"，是"让模型不用找"。** 第一代的问题是它刚看的东西会被折叠收走，所以它必须反复找；第二代的问题是它看到的是 2000 字符的锁孔，所以它必须一寸寸找。第三代把"找"这个动作整个从流程里删掉了——文件地图告诉它去哪儿，分段引导告诉它怎么切，零截断保证它看到的就是全部。

**这也是为什么我们后来把"文件地图"和"锚点自愈"（编辑未命中时把最近的原文行号回给模型，让它一次修正而不是整文件重读）归到同一类机制下**：它们不提高模型的任何能力，只是把"本来要花一步才能找回的东西"提前放到它眼前。**省下的那一步，就是省下的钱。**

## 两次翻车，一个共同的形状

把两次失败并排看，会发现它们有一个共同的形状——**都发生在"模型必须靠上下文才能记住自己干了什么"的那条链路上。**

第一代：模型读了文件，折叠把这次读取收走，模型不再记得读过什么，只能重读。
第二代：模型读了文件，截断只留前 2000 字符，模型记得自己读过、但不记得读到了什么，只能一寸寸补。

**两次翻车的受害者都是"模型自己的记忆"，两次的凶手都是"想省上下文的机制"。** 这不是巧合——执行期的截断和折叠，动的恰恰是"模型当前这一轮的工作记忆"。你在一个人正在干活的时候，把他刚摊在桌上的东西收走，他不会变高效，只会反复回头找。

所以这两次翻车指向的是同一条设计纪律，也就是后来定稿的那句：**执行期零截断。** 不是"少截一点"，是"执行期不碰"。因为只要执行期还有任何形式的收走动作，模型就永远有一个理由回头找——而回头找的每一步，都是全价计费、都有可能沉没。

## 为什么"读多少次"是一个好指标

这篇复盘里最常被引用的数字不是 token，是**读取次数**。值得说一句为什么我们最后把它当成了主指标。

token 会骗人——名义和等效能差一个数量级，折扣档位一换，绝对值就变。产出也会骗人——一次"完成了"背后可能是模型碰巧走对了路。但**读取次数不骗人**：它直接量的是"模型有多少步花在了找回材料上"。**一个任务如果读取次数逼近理论最小值，它就没有浪费的步；一次读取如果大量重叠，它就有真实的返工。**

更妙的是，这个指标**跨机制、跨模型都可比**。第一代 39 次、第二代 11 次、第三代 3 次——三代机制、同一任务，这个数一路往下，方向干净得不需要解释。**在一个 n=1、模型有非确定性、成本口径还会随折扣漂移的实验里，我们需要一个"无论怎么换算法都往同一个方向动"的量**——读取次数恰好就是它。

这也是为什么我们后来越来越不信"名义 token 降了多少"，越来越信"读取次数降到多少"。**前者是账面的说法，后者是流程的实相。**

## 一个机制清单，钉住每一项
实验跑完之后，我们不只是记了结论，还给每一项修复都钉了一条实测证据。这张清单的意义在于：**它把"我们的直觉变对了"变成了"我们能看到哪一次改动对应哪一段数据"。**

| 修复项 | 证据 |
|---|---|
| 轮内赦免（折叠废除） | 尝试 3 读取区间零重叠；对照尝试 1 的重叠序列 |
| 2KB 截断废除 | 3 次读取即覆盖全文；18 次编辑全部成功 |
| 开放轮 usage 记账 | 尝试 2 的 110,080 沉没成本留下了"轮未闭合"记录 |
| usage 落盘含缓存字段 | 本轮 89.8% 命中率可直接从 `task.json` 查得 |
| `read_file` 大块读取引导 | 恰好 3 次 × 400 行，无碎读 |
| Ctrl+C 中断友好化 | 尝试 2 中断后轮保持开放、数据完整、可继续 |

这张表里有一行看着不起眼，其实很关键：**"开放轮 usage 记账"。** 尝试 1 那一代**根本无法记账**——当时的开放轮没有 usage 记录，所以第一代那 39 次重读、40 步烧完的血账，**一个 token 数都没留下**。这是一个很实在的教训：**你没法优化的东西，首先是因为你没法测量它。** 第二代的 110,080 之所以能成为整篇文章最有力的数字，是因为记账缺口在这一代被修上了。**先有账，才有这篇复盘。**

顺带一提，"Ctrl+C 中断友好化"也是这个实验逼出来的。尝试 2 是被用户中断的，而中断后系统让那一轮保持开放、数据完整、可继续——**如果中断等于数据丢失，那我们连尝试 2 这笔账都拿不到。** 一个能"被打断而不丢账"的运行时，才有资格做这种需要中途叫停的实验。

## 说清楚我们有多不确定

这一篇的读数很干净，但边界和后一篇一样要写清楚。

**一、n=1。** 文档里那段诚实声明我们原样引用：

> **诚实声明**：n=1，模型输出有非确定性；B 是不同对话的参照而非严格对照。结论的强度来自**三代机制在同一任务上的方向一致性，而非统计显著性**。

最后半句才是重点。**我们信的不是"39 vs 3 这个读数"，是"三代机制在同一个任务上，方向一直指向同一个地方"。** 39 → 11 → 3 这条曲线跨了三代机制，每一代都往同一个方向动——这种方向一致性，比任何单个数字都更像结论。

**二、方向干净不等于因果干净。** 第二代到第三代之间，除了废除 2KB 截断，还一起加了**窗口保底**和**文件地图**。也就是说，**"3 次读取"里有几成是零截断的功劳、几成是文件地图的功劳，这批数据分不开。** 我们在文章里把它们分开讲，是因为后续的机制验证清单把每一项都对上了证据；但只看那条 39→11→3 的曲线，是分不出来的。**方向一致是"值得继续查"的理由，不是"已经查清"的理由。**

**三、这不是一个严格的三方对照。** 三代机制是在同一个会话里、随时间推进各跑一次，不是"A/B/C 三组并行互不相干"的那种对照。尝试 2 到尝试 3 之间有机制迭代，这既是我们要测的变量，也是时间、状态上前进了的事实。

这里要补一句更扎心的：**下面那个 B 参照组，是"另一场对话的参照"，不是严格对照。** 文档里写的是"9/4 晚 baseline 会话对同一网页的迭代作参照"——它是同一份网页、同一类任务，但它**不是在这个会话里、在同一时刻、用同一套记账跑出来的**。所以那个 382,199 的名义 token、以及它"记得全文所以一次通读都不用"的表现，只能当作一个**旁证**，不能当成本次三代实验的对照组。**我们真正能对着回答问题的，只有尝试 2 和尝试 3 这一对同会话的邻居。**

**四、这份文档标了"淘汰"，但结论仍在被引用。** 它记录的三代机制早就被后续版本取代了，里面的数字是**历史证据**，不是现役性能。我们引用它，是因为那条设计规则——执行期零截断——**至今是封版的不变量**。

**五、那个"11 次读取"的口径在不同文档里计数略有差异**（另一份文档写的是"2KB 锁孔时代 11 次读取全部沉没"）。数字是一致的，但**它来自单次运行**，别当精确刻度用。

**六、环比折扣率是假设值。** 表里那个"等效输入 ≈16,675 / 45,612"是按命中 30 倍折扣算的（未命中 + 命中/30）。折扣率是服务商的参数，不是我们的常数——换成别的折扣档位，这两个绝对值都会变。**但两轮的相对关系不会变**：失败轮的名义更低、命中率略低、等效更低，而产出为零。**我们据以推翻截断的，是这个相对关系，不是那两个绝对值。**

## 踩过的坑

**坑一：以为"模型看不见"就等于"模型会省着用"。**

第一代折叠的逻辑其实很顺：内容重复了，折掉它，模型就少看一点、便宜一点。但它漏了一件事——**折叠会把模型"自己刚读到的内容"也收走。** 于是模型不是少看，是**忘了再看**。我们从没想过"给它少一点"会诱发"它多读几遍"，因为直觉上"少"和"多"是反的。**上下文里少给的东西，模型会用重读加倍买回来——这个正反馈，只有账本能测出来。**

这里还有一个更细的认知错位：我们一开始以为折叠省的是"重复内容"，但实测重叠的是**同一段代码被反复请求**——也就是说，被折掉的恰恰是模型最需要的那部分。**"重复"和"重要"在这件事上是同一批内容，折叠分不开它们。**

**坑二：把"截断"当成一个无害的旋钮。**

我们一度觉得 2KB 截断是个可以调的参数——"先截狠一点，不行再放宽"。**但它不是旋钮，它是待机陷阱。** 一旦结果被截到 2000 字符，模型就掉进"一寸一寸蹭文件"的模式，而它在那个模式里做的每一次读取都是全价计费、全部有可能沉没。**一个"省一点"的默认值，把一个能一轮干完的活变成了一个永远干不完的活。** 旋钮和陷阱的区别是：旋钮转错了能转回来，陷阱进去了，那一轮的 token 就已经没了。

**坑三：以为"给个兜底工具"就兜住了。**

`expand_history` 就是那个兜底——内容被截了？展开完整原文就行。**设计意图没问题，但它的上限被写死在一个数值上（`[:4000]`），对将近 20KB 的结果根本兜不住。** 模型一次都没调用它。**这件事最深的教训不是"工具要写对"，是"一个坏掉的把手会被模型正确地绕开，而绕路的代价由我们付"。** 现在再看工具设计，我们会问的是："这个承诺，在它最该兑现的那个体量上，兑现得了吗？"

**坑四：盯着名义 token 做了太久的判断。**

37 万 vs 11 万——本能会指向"37 万那个贵"。我们最初也这么觉得，差点把零截断当成一次"为了质量牺牲成本"的妥协。**直到账本按缓存把两个数折算完，才发现反了：贵的那个是 11 万那轮，因为它一分产出都没有。** 名义 token 是"说了多少话"，等效输入是"真正付了多少钱"——**这两者在缓存定价下能差一个数量级，只看前者，你会对着 37 万惊慌、对着 11 万放心，而这两者谁贵谁便宜，恰好是反的。**

**坑五：想用"更多验证"来补"坏掉的机制"。**

第二代失败之后，有一闪而过的念头是"是不是该让模型更小心地读、多试几次"。**但那是在给一个结构性问题贴创可贴**——问题不在模型不够小心，在它面前只有一个 2000 字符的锁孔，再怎么小心也蹭不快。**方向错的时候，"更努力"是无效的，甚至会烧掉更多 token。** 我们最后是换了机制（零截断 + 文件地图），不是教育模型。

**坑六：把"降下来了"直接归功给最后那次改动。**

39 → 11 → 3 这条曲线很漂亮，漂亮到容易让人以为"零截断一步到位"。**但第三代那两个配套机制（窗口保底、文件地图）和第二代就不一样了**，"3 次读取"里有多少是零截断的功劳、多少是文件地图的功劳，这批数据其实分不开。我们在文章里分开讲，是因为后续的机制验证清单逐项对上了证据；但**如果只看那条曲线，它是分不出来的**。这提醒我们：一个下降的指标，往往同时是好几处改动叠出来的——**别把功劳记给最后一个动手的人。**

## 最后：省的不是钱，是步数
把这一篇收成三句话。

**第一句的落地方式，是"把钱花在看得见的地方"。** 零截断听着像"奢侈"，其实它是把预算从"反复重读"挪到了"一次读完"——同样是花钱，一笔买的是失忆，一笔买的是材料。**我们选择把钱花在让模型看得全上，而不是花在让它看得少、然后自己找回来上。**

**第一，截断省下的不是钱，是"模型自己刚看过的东西"。** 它进入上下文的账是虚的，进入重读的账是实的——而重读按全价计费。**省的方向和贵的来源，恰好相反。**

**第二，一个机制"更便宜"只在"活干成了"的前提下成立。** 110,080 对 374,732，账面看着是前者便宜；零编辑对十六组功能，账本上是后者便宜。**成本的单位不是 token，是"完成一步任务所付的 token"。** 把零产出的那 11 万省下来，不叫省钱，叫白花钱。

**第三，执行期不该省，该省的地方在整理侧。** 这是这一代机制迭代的最终定稿，也是这个系列第一句被封版的不变量。**压缩只属于整理侧**——因为整理是一次性的、有明确边界的、能主动选择切在哪的；而执行期是模型干活的现场，在那儿动手，等于在它眼前抽走它的材料。

这三句话里，第一句是成本直觉，第二句是验收纪律，第三句是机制边界。**它们是同一堵墙的三面**：截断号称省成本，其实把成本挪到了重读上（第一句）；它号称让任务更轻，其实让一次能完的活永远完不成（第二句）；它站在了不该站的位置——执行期（第三句）。**一个直觉、一个验证口径、一条边界，三代机制才把这堵墙拆干净。**

回头看那条 39 → 11 → 3 的曲线：它降下来的从来不是"模型变聪明了"，是**我们把"它在找什么"这个问题，直接从上下文里消掉了。** 第一代让它反复找，第二代让它一寸寸找，第三代让它一眼就看见——**三次读取，恰好是理论最小值；没有任何一步花在"找回本该在眼前的东西"上。**

下一篇回到那个被判死的架构——多 agent。讲一个被四个字概括错的结论，和一场我们解剖了半个多月的实验：对照组被污染、基线资格被质疑、又被一把新造的量尺救回来一半。**它不是一个"多 agent 不好"的故事，因为它最后的结局是复活的——只是复活成了另一个东西。**
